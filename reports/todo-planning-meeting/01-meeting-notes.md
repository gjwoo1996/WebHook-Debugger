## Meeting Purpose

현재 프로젝트의 주제를 TODO 애플리케이션으로 전환하기 전에, Notion에 정리된 TickTick/Todoist 분석 내용을 함께 읽고 필요한 기능만 선별한다.

기획 방향은 많은 기능을 그대로 따라가는 것이 아니라, 필요한 기능은 유지하되 사용자가 최대한 편하게 사용할 수 있도록 단순하고 직관적인 경험을 만드는 것이다.

## Decisions So Far

### 1. 할 일 추가 방식

결정: 한 줄 빠른 추가와 자세한 추가 화면을 모두 제공한다.

- 기본 화면에는 한 줄 빠른 추가 입력창을 둔다.
- 사용자는 할 일을 입력하고 Enter 또는 추가 버튼으로 바로 등록할 수 있다.
- 자세히 입력하고 싶을 때는 추가 화면 또는 상세 화면을 열 수 있다.
- 상세 화면에서는 메모, 날짜, 중요도 같은 선택 정보를 입력한다.

### 2. 날짜 지정 방식

결정: 단순 선택, 확장 선택, 자연어 입력을 모두 제공한다.

- MVP에서는 날짜 없음 / 오늘 / 내일 / 직접 선택을 제공한다.
- 이번 주 / 다음 주 / 나중에는 확장 날짜 옵션으로 고려한다.
- 자연어 입력은 확장 기능으로 둔다.
- 자연어 인식은 사용자가 확인하거나 해제할 수 있어야 한다.

### 3. 분류 방식

결정: 목록과 태그를 모두 제공한다.

- 목록은 할 일이 속한 큰 공간이다.
- 태그는 상황이나 맥락을 표시한다.
- 처음에는 목록 중심으로 보여준다.
- 태그는 추가 옵션 안에 둔다.

### 4. 우선순위

결정: 낮음 / 보통 / 높음 3단계로 제공한다.

- 기본값은 보통이다.
- P1/P2/P3 같은 표현은 사용하지 않는다.
- 색상만으로 구분하지 않고 텍스트도 함께 표시한다.

### 5. 반복 할 일

결정: MVP에서는 단순 반복만 제공한다.

- MVP: 매일 / 매주 / 매월 / 매년
- 확장: 평일마다, 주말마다, 특정 요일, 매월 마지막 날, N일마다, 완료일 기준 반복, 종료일 설정

### 6. 보기 방식

결정: 리스트 보기, 캘린더 보기, 보드 보기를 모두 제공한다.

- 리스트 보기는 기본 화면이다.
- 캘린더 보기는 날짜가 있는 할 일을 일정처럼 확인할 때 사용한다.
- 보드 보기는 진행 단계가 있는 일이나 프로젝트성 할 일을 관리할 때 사용한다.

### 7. 완료 처리와 보관 방식

결정: 오늘은 흐리게 남기고, 다음 날부터 완료 목록으로 이동한다.

- 완료된 항목은 같은 날에는 기존 목록에 남긴다.
- 다음 날부터는 기본 목록에서 숨기고 완료 목록에서 볼 수 있게 한다.
- 완료 항목은 필요하면 되돌릴 수 있어야 한다.

### 8. 삭제 방식

결정: 삭제하면 휴지통으로 이동하고 나중에 복구 가능하게 한다.

- 삭제된 할 일은 휴지통으로 이동한다.
- 휴지통에서는 복구 또는 영구 삭제를 할 수 있다.
- 삭제 직후에는 되돌리기 안내를 보여준다.

### 9. 검색과 필터

결정: 검색과 기본 필터를 제공한다.

- 사용자는 할 일 제목과 메모를 검색할 수 있다.
- 기본 필터를 제공한다.
- 저장 필터는 초기 범위에서 제외한다.

### 10. 빈 화면과 안내 방식

결정: 안내 문구와 예시 할 일/템플릿을 제공한다.

- 처음 사용하는 화면에는 단순히 비어 있다고만 말하지 않는다.
- 사용자가 바로 시작할 수 있는 예시를 제공한다.
- 템플릿은 강요하지 않고 선택지로만 제공한다.

### 11. 알림/리마인더

결정: MVP에서는 제외하고 확장 기능으로 둔다.

- 웹 프로젝트에서는 브라우저 알림 권한, OS/브라우저 차이, 서버 기반 Web Push 필요성 같은 한계가 있다.
- 앱 내부 리마인더와 선택적 브라우저 알림은 확장 기능으로 둔다.

### 12. 계정과 저장 방식

결정: 로그인 기반 서버 저장을 사용한다.

- 사용자의 할 일은 서버에 저장한다.
- 계정 기반으로 여러 기기에서 같은 데이터를 볼 수 있게 한다.
- 로그인 후에는 바로 할 일을 추가할 수 있는 화면으로 이동한다.

### 13. 협업 기능

결정: 초기에는 개인용만 제공한다.

- 목록 공유, 담당자 지정, 댓글, 활동 기록은 초기 범위에서 제외한다.
- 앱의 핵심은 개인의 할 일 수집, 정리, 실행에 둔다.

### 14. 개인화/설정

결정: 설정은 최소화한다.

- 대부분의 값은 좋은 기본값을 제공한다.
- 사용자가 앱을 쓰기 전에 설정해야 하는 항목을 만들지 않는다.
- 다크 모드, 화면 밀도, 세부 기본값 설정은 후순위로 둔다.
