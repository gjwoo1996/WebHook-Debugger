# 커밋 작업 규칙

이 문서는 AI가 커밋을 만들거나 커밋 메시지를 제안할 때 반복적으로 발생하는
문제를 줄이기 위한 규칙입니다. 커밋 작업을 시작하기 전에 반드시 이 문서를
먼저 확인합니다.

## 핵심 원칙

- 커밋하기 전에 반드시 수정사항을 확인합니다.
- 모든 수정사항을 하나의 커밋으로 묶지 않습니다.
- 변경 목적과 성격이 다른 작업은 커밋을 나눕니다.
- 커밋 메시지는 한글로 작성할 수 있습니다.
- 커밋 메시지는 최대한 자세히 작성하되, 읽기 쉬운 구조를 유지합니다.
- 사용자가 명시적으로 요청하지 않은 파일은 커밋에 포함하지 않습니다.

## 커밋 전 확인 절차

커밋을 만들기 전에는 아래 순서로 확인합니다.

1. `git status --short`로 변경된 파일 목록을 확인합니다.
2. `git diff`로 실제 수정 내용을 확인합니다.
3. 새 파일은 `git diff --cached`만으로 보이지 않을 수 있으므로 파일 내용을
   직접 확인합니다.
4. 변경사항을 성격별로 분류합니다.
5. 각 커밋에 포함할 파일 또는 hunk를 결정합니다.
6. 커밋 메시지를 작성하기 전에 해당 커밋의 목적을 한 문장으로 정리합니다.

## 커밋 분리 기준

아래 항목이 서로 섞여 있다면 커밋을 나눕니다.

- 기능 추가
- 버그 수정
- 리팩터링
- 문서 수정
- 테스트 추가 또는 수정
- 설정 변경
- 의존성 변경
- 포맷팅만 변경된 작업
- 파일 이동 또는 이름 변경

예시:

```text
docs: 문서 구조를 영문/한글 디렉토리로 분리
docs: AI 커밋 작업 규칙 문서 추가
chore: 개발 컨테이너 설정 정리
```

## 하나의 커밋에 포함해도 되는 경우

아래처럼 하나의 목적을 달성하기 위해 함께 필요한 변경은 같은 커밋에 포함할
수 있습니다.

- 기능 코드와 해당 기능의 테스트
- 문서 파일 이동과 그에 따른 README 링크 수정
- 설정 파일 변경과 해당 설정을 설명하는 짧은 문서 수정
- 파일명 변경과 참조 경로 수정

단, 함께 포함하는 이유가 명확해야 합니다.

## 커밋 메시지 작성 규칙

커밋 메시지는 Conventional Commits 형식을 기본으로 사용합니다.

```text
<type>: <요약>

<본문>
```

사용 가능한 type 예시:

- `feat`: 기능 추가
- `fix`: 버그 수정
- `docs`: 문서 추가, 수정, 이동
- `refactor`: 동작 변경 없는 구조 개선
- `test`: 테스트 추가 또는 수정
- `chore`: 빌드, 설정, 도구, 기타 작업
- `style`: 포맷팅, 세미콜론, 공백 등 동작과 무관한 스타일 수정

## 좋은 커밋 메시지 예시

```text
docs: AI 커밋 작업 규칙 문서 추가

커밋 전에 변경사항을 확인하고 성격별로 커밋을 분리하도록
AI 작업 규칙을 문서화했다.

또한 커밋 메시지를 한글로 작성할 수 있도록 예시와 작성 기준을
함께 정리했다.
```

```text
docs: 한글 문서 파일명을 한국어로 변경

docs/ko 아래 문서들이 한글 번역본임에도 영어 파일명을 사용하고 있어
문서명을 한국어로 변경했다.

README의 문서 링크도 변경된 파일명에 맞게 갱신했다.
```

## 피해야 할 커밋 메시지

아래처럼 너무 짧거나 의미가 불분명한 메시지는 피합니다.

```text
update
fix
docs
수정
작업
문서 수정
```

## AI가 특히 주의할 점

- 사용자의 작업으로 보이는 변경사항을 임의로 되돌리지 않습니다.
- 관련 없는 변경사항을 커밋에 끼워 넣지 않습니다.
- 커밋을 만들기 전에 어떤 파일을 포함할지 사용자에게 설명합니다.
- 여러 성격의 변경이 섞여 있으면 커밋 분리안을 먼저 제안합니다.
- 커밋 메시지 본문에는 “무엇을”, “왜” 변경했는지 적습니다.
- 구현 세부사항이 많을 때는 bullet을 사용해 가독성을 높입니다.

## 커밋 분리안 보고 형식

커밋을 만들기 전 사용자에게 아래 형식으로 보고합니다.

```text
현재 변경사항은 다음 커밋으로 나누는 것을 추천합니다.

1. docs: 문서 구조 정리
   - README 문서 인덱스 추가
   - docs/en, docs/ko 문서 구조 추가

2. docs: AI 커밋 작업 규칙 추가
   - docs/ai/en/commit-guidelines.md 추가
   - docs/ai/ko/커밋 작업 규칙.md 추가
   - AGENTS.md에 커밋 전 확인 규칙 연결
```

## 최종 확인

커밋 직전에는 다음을 확인합니다.

- 이 커밋에 포함된 변경사항이 하나의 목적을 가지는가?
- 커밋 메시지만 읽어도 변경 이유를 이해할 수 있는가?
- 사용자 변경사항을 실수로 포함하지 않았는가?
- 불필요한 임시 파일이나 테스트 파일이 포함되지 않았는가?
- 문서 링크나 파일 경로를 바꿨다면 실제로 존재하는 경로인가?
