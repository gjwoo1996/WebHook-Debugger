# 브랜치 전략

## 브랜치 구조

```text
main
  -> dev
      -> feat/endpoint-create
      -> feat/webhook-receive
      -> feat/realtime-websocket
      -> feat/request-replay
```

## 브랜치 역할

- `main`: production 또는 demo 배포 브랜치. 직접 push 금지
- `dev`: 개발 통합 브랜치
- `feat/*`: pull request를 통해 `dev`로 merge되는 기능 브랜치
- `fix/*`: pull request를 통해 `dev`로 merge되는 버그 수정 브랜치
- `docs/*`: 문서 전용 브랜치

## Pull Request 규칙

- 관련 issue 연결
- 하나의 기능 또는 수정에 집중
- 검증 방법 포함
- merge 전 최소 1명에게 리뷰 요청
