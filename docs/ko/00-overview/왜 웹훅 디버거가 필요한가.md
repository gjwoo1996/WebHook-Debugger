# 왜 WebHook Debugger가 필요한가

## localhost는 외부 웹훅을 받을 수 없음

개발 중 백엔드는 보통 개발자의 로컬 머신에서 실행됩니다.

```text
결제 서비스 -> localhost:8080  X
```

외부 서비스는 이 주소에 접근할 수 없습니다. 외부 서비스 입장에서
`localhost`는 개발자의 컴퓨터가 아니라 외부 서비스 자신의 머신을 의미하기
때문입니다.

## 흔한 불편함

- 실제 웹훅 요청을 받으려면 먼저 배포해야 함
- 배포, 테스트, 수정, 재배포 반복으로 시간이 낭비됨
- 헤더와 원본 request body를 나중에 확인하기 어려움
- 같은 이벤트를 재현하려면 실제 외부 이벤트를 다시 발생시켜야 함
- status code와 반복 요청을 보지 않으면 retry 동작을 이해하기 어려움
- 팀원이 같은 요청을 공유하며 디버깅하기 어려움

## 해결 방향

WebHook Debugger는 공개 수신 URL을 제공하고 들어온 요청을 저장합니다.
브라우저에서는 요청을 실시간으로 확인할 수 있고, 개발자는 저장된 요청을
로컬 또는 원격 서버로 다시 전송할 수 있습니다.

```text
외부 서비스 -> 디버거 공개 URL -> 저장 및 표시 -> 대상 서버로 재전송
```

## 협업 프로젝트로 좋은 이유

- 실제 개발에서 자주 마주치는 문제를 다룸
- 제품 흐름이 명확함
- 기능이 프론트엔드, 백엔드, 인프라, 협업 작업으로 자연스럽게 나뉨
- Webhook.site, RequestBin 같은 기존 도구가 있어 수요가 검증됨
- HTTP, WebSocket, 인증, 저장소, 보안, Docker, CI/CD, 클라우드 배포를
  실무적으로 다룰 수 있음
