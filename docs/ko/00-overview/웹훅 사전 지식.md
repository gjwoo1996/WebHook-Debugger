# 웹훅 사전 지식

## 웹훅이란?

웹훅은 특정 이벤트가 발생했을 때 한 시스템이 다른 시스템으로 보내는 HTTP
콜백입니다. 개발자가 외부 서비스에 URL을 미리 등록해두면, 외부 서비스는
이벤트가 발생했을 때 해당 URL로 요청을 보냅니다.

대표적인 예시는 다음과 같습니다.

- 결제 서비스가 `payment.completed` 이벤트를 전송
- GitHub가 `push` 또는 `pull_request` 이벤트를 전송
- 메시징 서비스가 메시지 전달 상태를 전송
- CI/CD 시스템이 빌드 완료 알림을 전송

## 웹훅과 Polling의 차이

Polling은 클라이언트가 서버에 변경 여부를 반복해서 묻는 방식입니다. 웹훅은
흐름이 반대입니다. 이벤트가 발생했을 때 이벤트를 가진 외부 서비스가 직접
요청을 보냅니다.

| 항목 | Polling | Webhook |
| --- | --- | --- |
| 트리거 | 클라이언트가 반복 조회 | 외부 서비스가 이벤트 발생 시 전송 |
| 네트워크 비용 | 불필요한 요청이 생길 수 있음 | 이벤트 기반이라 효율적 |
| 지연 시간 | 조회 주기에 따라 달라짐 | 거의 실시간 |
| 개발 난점 | 반복 호출과 스케줄링 | 공개 콜백 URL과 요청 검증 |

## 기본 개념

- Callback URL: 외부 서비스에 등록하는 수신 URL
- HTTP method: 보통 `POST`를 쓰지만 서비스에 따라 다른 method도 가능
- Headers: content type, signature, user agent, request ID 같은 메타데이터
- Body: 이벤트 payload이며 주로 JSON 형식
- Status code: 수신 서버의 응답 코드이며, 일부 서비스는 오류 코드에서 재시도
- Signature verification: 요청이 신뢰할 수 있는 서비스에서 왔는지 확인하는 절차
