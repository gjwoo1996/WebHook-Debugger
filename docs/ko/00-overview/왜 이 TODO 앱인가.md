# 왜 이 TODO 앱인가

## 문제

많은 TODO 앱은 강력하지만 복잡합니다. 처음 쓰는 사용자는 단순히 할 일을
적기 전에 먼저 앱의 체계를 배워야 한다고 느낄 수 있습니다. 태그, 필터,
보드, 반복, 알림 같은 고급 기능은 가장 중요한 행동인 "오늘 무엇을 할지
정하기"와 화면 공간을 두고 경쟁하기도 합니다.

## 제품 방향

이 프로젝트는 처음에는 단순하고, 필요할 때 점진적으로 확장되는 TODO 앱을
만듭니다.

기본 경험은 오늘 할 일과 빠른 수집에 집중합니다. 사용자는 날짜, 목록, 태그,
우선순위, 반복, 캘린더, 보드가 필요해졌을 때 해당 기능을 사용할 수 있지만,
앱은 사용자가 할 일을 관리하기 전부터 많은 결정을 요구하지 않습니다.

## 협업 프로젝트로 좋은 이유

- 인증, 저장, 할 일 CRUD, 검색, 필터, 여러 보기처럼 풀스택 경계가 명확함
- 빈 화면, 상세 패널, 모달, 캘린더, 보드 상호작용 같은 실용적인 프론트엔드
  상태를 다룰 수 있음
- 백엔드는 실제 제품 데이터를 모델링하되 1개월 프로젝트 범위를 넘지 않음
- 팀이 제품 회의 결과를 양국어 문서, API 설계, 구현 작업, 테스트 가능한
  기능으로 옮기는 연습을 할 수 있음
