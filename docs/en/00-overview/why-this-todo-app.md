# Why This TODO App

## The Problem

Many TODO apps are powerful but busy. New users can feel that they must learn a
system before they can simply write down a task. Advanced features such as tags,
filters, boards, recurring tasks, and notifications can also compete for space
with the most important action: deciding what to do today.

## Product Direction

This project builds a TODO app that starts simple and expands gradually.

The default experience focuses on today's tasks and fast task capture. Users can
add dates, lists, tags, priorities, repetition, calendar views, and board views
when those tools become useful, but the product should not force those decisions
before the user has tasks to manage.

## Why This Is a Good Collaboration Project

- The product has clear full-stack boundaries: authentication, persistence,
  task CRUD, search, filters, and multiple views.
- The frontend includes practical UI states such as empty screens, detail
  panels, modals, calendar layouts, and board interactions.
- The backend can model real product data without becoming too large for a
  one-month project.
- The team can practice turning product meetings into bilingual documentation,
  API design, implementation tasks, and testable features.
